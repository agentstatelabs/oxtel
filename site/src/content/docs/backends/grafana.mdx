Grafana shows telemetry that other programs keep: here, traces in Tempo, logs in Loki and metrics in Prometheus. Each of the three takes OTLP itself, so oxtel sends each kind of telemetry straight to the one that keeps it, with nothing in between. Grafana then links them: from a log line to its trace, and from a trace to its log lines.

## Send to it

Set these where your program runs, then start it:

<Example file="examples/backends/grafana/settings.sh" />

Each kind of telemetry has its own endpoint, used exactly as given, so each needs its full path. Open http://localhost:3300 and go to Explore:

- **Logs:** choose Loki and query `{service_name="worker"}`. Loki turns `service.name` into the label `service_name`, and keeps each line's trace id beside it, so a line written inside a span links to its trace.
- **Traces:** choose Tempo and search for the service, or query `{resource.service.name="worker"}`.
- **Metrics:** choose Prometheus and query `jobs_processed_total{job="worker"}`. For a web service with oxtel-tower, `http_server_request_duration_seconds_count` counts its requests, by `http_route` and `http_response_status_code`. [Prometheus](/backends/prometheus/#the-names-in-prometheus) explains how the names change.

Metrics are sent every minute by default, and when the program stops; the settings above send them every 5 seconds while you try it out. Spans and log records go within a few seconds.

## In production

- **A Collector in front** is common: programs send everything to one address, and the [Collector](/backends/collector/) sends each kind on, with batching, retries, and the credentials in one place. Set `OTEL_EXPORTER_OTLP_ENDPOINT` to the Collector, instead of the three endpoints.
- **Storage:** this Tempo keeps traces on the container's disk, and Loki and Prometheus their defaults, all lost with the containers. Grafana's documentation covers running each to keep data.
- **Signing in:** this Grafana lets anyone in as an administrator. Remove the `GF_AUTH_` settings anywhere but your own machine.

## How it's checked

On every change, CI starts this stack, runs [the background worker](/scenarios/worker/) with these settings, and asks Tempo for its traces, Loki for its failed job's log line and Prometheus for its `jobs.processed` counter. It also asks Grafana whether each data source works. `check.sh`, beside the compose file, has the queries.
