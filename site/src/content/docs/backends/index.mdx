title: Backends

import { CardGrid, LinkCard } from '@astrojs/starlight/components';

A backend keeps telemetry and lets you search it. oxtel speaks OTLP, which almost every backend takes, so sending to one is a matter of settings, not code. Each page here has a stack to run with `docker compose`, the settings that send to it, and where to look once telemetry arrives.

| Backend | What it keeps | How oxtel reaches it |
|---|---|---|
| [Elastic](/backends/elastic/) | Traces, metrics and logs | OTLP to APM Server, or log lines for a shipper |
| [Grafana, Tempo and Loki](/backends/grafana/) | Traces in Tempo, logs in Loki, metrics in Prometheus | OTLP to each |
| [Hosted backends](/backends/hosted/) | Whatever the service keeps | OTLP, with a key in a header |
| [Jaeger](/backends/jaeger/) | Traces | OTLP |
| [The OpenTelemetry Collector](/backends/collector/) | Nothing: it sends telemetry on, to backends of your choice | OTLP |
| [Prometheus](/backends/prometheus/) | Metrics | Scraping `/metrics`, or OTLP |

Every stack here runs in CI on every change: CI starts it, runs [the background worker](/scenarios/worker/) with the page's settings, and checks the backend has the worker's telemetry, with the same files the pages show. They're in the repository's [`examples/backends/`](https://github.com/agentstatelabs/oxtel/tree/main/examples/backends), with `run.sh` to run the checks yourself; or copy the files from the pages into a directory of your own.
