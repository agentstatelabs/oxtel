Each recipe is a few settings, or a few lines of code, for one common situation.

## JSON logs in a container

Nothing to do: when standard error isn't a terminal, oxtel writes one JSON object per line, which every log shipper understands. To be explicit, set `OXTEL_LOG_FORMAT=json`. If your platform only collects standard output, set `OXTEL_LOG_OUTPUT=stdout`.

## A backend

Sending to a backend is a matter of settings. [Backends](/backends/) has a page for each common one, with a stack to run on your machine and the settings that send to it:

- [Elastic](/backends/elastic/): over OTLP to APM Server, or as log lines in the Elastic Common Schema with `OXTEL_LOG_FORMAT=ecs`.
- [Grafana, Tempo and Loki](/backends/grafana/): traces, logs and metrics, each to the store that keeps it.
- [Hosted backends](/backends/hosted/): an endpoint and a key in a header.
- [Jaeger](/backends/jaeger/): traces.
- [The OpenTelemetry Collector](/backends/collector/): one address for your programs, sending on to any backend.
- [Prometheus](/backends/prometheus/): metrics, scraped from oxtel's `/metrics` or pushed over OTLP.

<Example file="examples/web.rs" region="serve" />

- Call `oxtel::init()` first, so the layer finds the metrics recorder.
- Shut down gracefully, as above. Otherwise Ctrl-C ends the process at once, before oxtel can send what's pending. Deployed, wait for SIGTERM too, which is how Docker, Kubernetes and systemd stop a program: [in a container](/deploy/docker/#stopping-cleanly) shows how.
- `.with_access_log(false)` drops the `request` lines; `RUST_LOG=info,oxtel_tower=warn` keeps only those for failed requests.

## An MCP server

Wrap the server with `oxtel_rmcp::Instrumented::new(server)` and serve the wrapper. Each request gets a span named for what it asks, such as `tools/call add`, continuing the client's trace if it sent one:

<Example file="examples/mcp-stdio.rs" region="serve" />

- Log lines go to standard error by default, which keeps them out of a stdio server's protocol stream. Don't set `OXTEL_LOG_OUTPUT=stdout` for one, or turn on a console exporter.
- `RUST_LOG=info,rmcp=warn` keeps rmcp's own lines and spans out of the way.
- Over streamable HTTP, rmcp takes a handler rather than a service: wrap the server in `oxtel_rmcp::InstrumentedHandler` instead.

[An MCP server over stdio](/scenarios/mcp-stdio/) and [an MCP server over HTTP](/scenarios/mcp-http/) have whole programs.

## Turning things off

- No log lines: `OXTEL_LOG_FORMAT=none`, or `.without_local_logs()` in code.
- Nothing at all except log lines: `OTEL_SDK_DISABLED=true`.
- One kind of telemetry: `OTEL_TRACES_EXPORTER=none`, `OTEL_METRICS_EXPORTER=none` or `OTEL_LOGS_EXPORTER=none`.
